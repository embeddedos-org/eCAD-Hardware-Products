# Memory

Durable context for `eCAD-Hardware-Products` — decisions and constraints that outlive one
session and are not recoverable from the code or the git history.

Write here when a future reader would otherwise repeat an argument that was
already settled, or repeat a mistake that was already made.

## What belongs here

- Decisions and the reason behind them, especially the options rejected.
- Constraints that are not visible in the code — a deadline, a compatibility
  promise, a hardware limitation, an external dependency's behaviour.
- Traps: things that look wrong but are deliberate, and things that look safe
  but break.

## What does not

- Anything derivable by reading the code.
- Anything in the git log.
- Task status — that is [TASKS.md](./TASKS.md).
- Standards — those are [QUALITY.md](./QUALITY.md),
  [TESTING.md](./TESTING.md) and [SECURITY-STANDARDS.md](./SECURITY-STANDARDS.md).

## Traps

Things that look wrong but are deliberate, and things that look safe but break.
Add an entry the first time something here costs someone an hour — that is the
threshold, and it is deliberately low.

- **Placed footprints have no pads.** This looks like an unfinished export. It is
  deliberate: a land pattern invented from a package name looks fabricable and is
  not. Assign real IPC-7351 footprints before layout.
- **The netlist has no signal nets.** Also deliberate — pin-level connectivity is
  not derivable from a bill of materials. The omission is stated in each `.net`
  header rather than filled with plausible guesses.
- **A green gate does not mean the CAD was checked.** Missing tools are reported
  as skips, never failures. On a machine without `kiutils`, `ezdxf` or OpenSCAD,
  the CAD checks silently do not run. Confirm the skip count is zero.
- **`generate_products.py` rewrites catalog JSON formatting** if a script edits it
  with `json.dump`. Nested arrays expand and diffs get noisy. Harmless, but do not
  mistake it for a content change.
- **OCCT prints transfer statistics to stdout from C++.** The importer's child marks its JSON line with a prefix; taking the last line of stdout can pick up kernel output instead.
- **The millimetre pin in the STEP importer is belt-and-braces.** OCCT's default session unit is already millimetres, so deleting the pin passes every test. What the tests protect is misreading the unit.
- **`detect_mujoco` probes `python3` on `PATH`, not the running interpreter.** From a virtual environment not first on `PATH`, MuJoCo cases report `MUJOCO_NOT_INSTALLED` even though MuJoCo is importable.
- **MuJoCo's `inertiafromgeom="false"` does not stop proxy boxes from colliding.** It only stops geometry setting mass. Every dynamics scenario therefore disables contact; only the clearance scenario sees the proxies.
- **A mutation test that survives may be a fixture fault, not a missing test.** A lever-arm sign mutant survived because the test joint's axis passed through the origin, where the mutated and correct formulas agree. `tests/mutation/run_mutations.py` records each mutant and the fixture choice that kills it.
- **OpenCASCADE's wheel needs `libGL.so.1`.** On a bare Debian image (`python:3.12-slim`) `import OCP` fails until `libgl1` is installed; nothing else was needed for the import (measured on aarch64, 2026-09-25). The `cad-dataset` job installs it rather than trusting the runner image.
- **MuJoCo cannot be imported under x86_64 emulation on Apple silicon.** The emulated CPU advertises no AVX (measured), and `import mujoco` aborts inside pybind11 -- or never returns: a probe container was found still running 15 hours later (2026-09-26). Give any emulated probe a time limit: macOS has no `timeout` binary, and `docker run --stop-timeout` only sets the grace period of a later `docker stop`, so run the probe detached and `docker stop` it after a deadline. An emulated x86_64 container verifies OpenCASCADE reproduction (`check` passes) but not the simulation stages; those need a native x86_64 runner.
- **OCCT writes a multi-file STEP assembly** with `STEPCAFControl_Writer.Transfer(doc, STEPControl_AsIs, "prefix_")`: one main file plus one file per part next to it. That is how the external-reference refusal is tested end to end.
- **`except LookupError` also catches `KeyError` and `IndexError`.** The first adapter version raised `LookupError` for a missing adapter and caught it, so every lookup the builder failed on an invalid item was reported as the domain being `NOT_IMPLEMENTED`. A missing adapter is now its own exception, `DomainNotImplemented`, decided before any derivation runs.
- **The case engine stops, not fails, on some documents.** `cases.py:156` reads a case document as UTF-8 and catches only `OSError` and `JSONDecodeError`, so a UTF-16 document -- which `json.loads(bytes)` parses happily -- raises `UnicodeDecodeError`; a document nested deeply enough raises `RecursionError` from its parse or its schema check; a metric that is not a finite number makes `canonical_json_bytes` raise. The dataset runner catches all three, and each loses the verdicts of the whole document (plan §7.2, ENGINE-1).
- **A case runs on derived files, so they are part of what must still reproduce.** Comparing the case objects alone counted a case whose MJCF input was stale: the fourth foundation review doubled the densities and got a verdict from the old model.
- **Python's `json` accepts `Infinity` and `NaN`, and an infinity is "within tolerance" of every number** (the tolerance is infinite too). Untrusted JSON goes through `dataset._json`, which refuses them.
- **A guard shadowed by another guard needs a test through the path only it covers.** Twice the full mutation run left one survivor for this reason: the stale-case filter was reached only by a document the fresh derivation still compiles, and the results' case-schema check only by regeneration from a forged run -- the tests written for each went through a path an earlier guard already closed.
- **Reconcile by content, not by id.** The third foundation review showed that a committed case keyed by the right id can still hold a limit nobody states any more; comparing ids alone passed a tightened limit against the old one.
- **The case engine reports an unparsable case document as `FAIL` with no evidence** (`cases.py:157-170`), which the receipt contract forbids, so the receipt fails its own schema. The dataset runner cites the document itself; the product pipeline still has the defect (plan §7.2, ENGINE-1).
- **The mutation harness copies the working tree for each mutant.** Editing code or tests while it runs gives later mutants a different baseline from earlier ones. Edit documentation only, or wait.
- **Verification containers fill the disk.** Linux runs under Colima leave exited containers and committed images inside `~/.lima`, and a full disk shows up as `ENOSPC` in unrelated tools. Removing this work's own containers and images and running `colima ssh -- sudo fstrim -av` returned about 17 GB (2026-09-26). Never remove containers this work did not create.
- **Negating 0.0 gives -0.0.** `-0.0 == 0.0`, so assertions pass, but JSON then carries `-0.0`. `canonical_direction` computes `0.0 - x` for this reason.
- **`ngspice -r` makes no measurements in batch mode, and `-o` takes them out of stdout.** With `-r` it prints "No .measure possible in batch mode (-b) with -r rawfile set!" to stderr and still exits 0; with `-o` the results go to the log file (Verified, ngspice-47, 2026-09-27). Either flag on the adapter's argv empties every metric without an error.
- **A `.meas` ngspice cannot make is absent from stdout, named on stderr (`.meas tran late find v(a) at=50u failed!`), and the exit status is 0.** A name declared twice is printed twice. Neither is an error to ngspice, so the adapter names both in its summary rather than trusting the exit code.
- **ngspice runs some comments.** A line below the title starting with `*#` (after any indentation) is a front-end command, `shell` included, even in `-b -n` batch mode and after `.end`; a title starting with `*ng_script` makes the whole file a script (Verified, ngspice-47, 2026-09-27). A reader that skips every `*` line as a comment misses both, so `ecad_model/spice.py` refuses them.
- **ngspice's stdout is not byte-identical run to run under load.** A transient that runs slowly (wall-clock) writes ` Reference value : <simulated time>` and a CR over a blank line of stdout, once or more (`run_process` reads stdout as text, so the CR arrives as a line end); `.options noacct` does not remove it, `.options norefvalue` does (Verified, ngspice-47, 2026-09-27). ngspice-36 writes the same report to stderr instead (Observed, 36+ds-1ubuntu0.1 in an ubuntu:22.04 arm64 container under load, 2026-09-27), so a check of stderr must allow it too. It never matches a measurement line, but two execution records of one deck can differ in it.
- **ngspice's output differs between versions.** For the deck committed on 2026-09-27 (nine measurements), ngspice-36 (ubuntu:22.04's apt) and 44.2 (Debian 13's) print seven of the nine `.meas` values to seven significant digits where 47 prints six (`4.791472e+01` against `4.79147e+01`); 36 also writes four `Warning: <source>: no DC value, transient time 0 value used` lines to stderr, prints `No compatibility mode selected!` without 47's `Note: `, and has no `Using SPARSE 1.3 as Direct Linear Solver` line; 44.2 differs from 47 in the digits only. - **ngspice-47 prints `.meas` values to six significant digits whatever `numdgt` says.** With `.options numdgt=12`, 1 V across 3 ohm still printed `3.33333e-01` (Verified, 2026-09-27). The electrical references' tolerances rest on that precision; the previous entry says what 36 and 44.2 print.
- **ngspice reads SPICE numbers case-insensitively and drops trailing letters.** 1 V across `1M` drew 1000 A (milli), across `1MEG` 1e-06 A, `10uF` 1e+05 A (10 micro-ohm), `2kohm` 5e-04 A, `1ms` 1000 A and `1mil` 3.93701e+04 A (25.4 micro); `10F` is femto, clamped to 1e-12 ohm with only a warning. A reader that accepts those spellings reads a different circuit from the one ngspice runs, which is why `ecad_model/spice.py` reads lower-case suffixes only.
- **`gnd` is ground to ngspice, and `par()` owns the nodes `pa_00`, `pa_01`, ...** A resistor to `gnd` conducts to node 0. A `.meas` that uses `par()` creates `pa_NN` nodes (they appear in the operating-point table), and a netlist node named `pa_00` is taken over: 1 V across 2 ohm read as 1.0 A instead of 0.5 A (Verified, ngspice-47, 2026-09-27).
- **ngspice owns more names than `gnd` and `pa_NN`.** In a `.meas`, a node named `time` reads as the time axis (`v(time)` at 5 us is 5e-06), `all` and `allv` as another vector, `alli` as no vector, `temper` crashes ngspice (SIGSEGV), and `limit`, `gauss`, `agauss`, `unif` or `aunif` inside `par()` make it exit 1; a switch model named `TEMPER` crashes it and one named `GND` is never found. A title or comment holding those words is harmless (Verified, ngspice-47, 2026-09-28). The parser therefore reads only `n_` nodes and `SW_` models. The probe: each of 174 names as the middle node of a 1k/1k divider, read by five `.meas` directly and inside `par()`, and as the model of a switch closing at 2 us; with the prefixes every one read correctly.

Every run exits 0 (Verified, ngspice-47, 2026-09-27).
- **`.control` blocks and a `.spiceinit` in the working directory run under `-b`.** `shell touch <file>` in a `.control` block created the file, and so did a `.spiceinit` in the directory ngspice ran in; `-n` stops only the `.spiceinit`, not a `*#` line (Verified, ngspice-47, 2026-09-27). Batch mode is not a sandbox.
- **`.options noacct` removes the operating-point table and the run statistics, not the progress report.** Without it, stdout also carries the "Initial Transient Solution" table and the analysis time, elapsed time and memory figures, which differ on every run; with it, two runs of the committed deck still differed in the ` Reference value :` line (`7.83155e-02` and `8.02525e-02`), and `.options noacct norefvalue` made two runs byte-identical (Verified, ngspice-47, 2026-09-27; see the progress-report entry above and plan §20 Q11). No such line is a measurement line.

In a clean clone of `57f4fee`, `v0.pinned-clean-source` was `PASS` `SOURCE_REVISION_PINNED`, and `BLOCKED` `SOURCE_TREE_DIRTY` once one such directory held a copy of the netlist (Verified, 2026-09-27). - **`iverilog -V` honours `IVERILOG_ICONFIG`.** Run with the caller's environment, `iverilog -V` writes its configuration dump (`basedir:`, `module:` lines) to the file the variable names (Verified, Icarus 13.0, 2026-09-27). The adapter's probe, `hdl.probe_iverilog`, runs it through `run_process` since the digital review (CS-6), as the compile and run steps always did, so a validation never writes it. `capabilities.probe_executable` still passes the caller's environment, so `detect_capabilities` (the `ecad_validation` CLI's capability listing) still writes it; scrubbing that changes every tool's probe, so it is its own change. A test that sets the variable and expects no file must not call `detect_capabilities`.
- **Patching `process.subprocess.run` patches `subprocess.run` everywhere.** `mock.patch("ecad_validation.adapters.process.subprocess.run")` replaces the attribute on the `subprocess` module itself, so any other process the code under test starts meets the same fake (and `process.shutil.which` is `shutil.which`). `tests/unit/test_hdl_adapter.py`'s fake answers `iverilog -V`, the adapter's version probe, separately, records how it was called, and counts only the two steps.
- **The Verilog grammar trusts Icarus to skip comments exactly as it does.** Directives and `$` names inside comments are accepted, because Icarus ignores them: `` // `include "<file>" ``, `` /* `include "<file>" */ `` and `// $fopen(...)` compiled with exit 0 and wrote nothing, and a `//` comment ending in a backslash does not swallow the next line (Verified, Icarus 13.0, 2026-09-27). - **Only Icarus 13 prints `<file>:<line>: $finish called at <t> (1ps)`.** Icarus 11.0 (the CI's apt version) prints no such line for the same file; the `ECAD_METRIC` lines are identical (the design's container log, 2026-09-27; Observed there, not re-run here). - **`0xA5` is a bit palindrome.** A receiver with its bit order reversed receives it unchanged: 0 bit errors on Icarus 13.0 (Verified, `test_rtl_defects_fail_their_references`, 2026-09-28). The digital sample sends `0x35` then `0xCA`, complements neither of which reads the same reversed; keep that property when changing the bytes. `0xCA`'s bit 0 is 0, which is also what shows a receiver whose bit 0 sticks at 1 (one bit error, Verified on Icarus 13.0, review HT-4): two odd bytes would hide that defect.
- **Where an option sits on the `iverilog` command line means different things on different hosts.** Icarus 13.0 on macOS reads `-s b` placed after the source files as a file name ("-s: No such file or directory", exit 1), and before them as the root to elaborate (Verified, 2026-09-29); Icarus 11.0 on ubuntu:22.04 parsed options after the files, so `iverilog ... file.v -N /tmp/x` wrote `/tmp/x` (the digital design's container run, 2026-09-27, not re-run here). A test of argument handling on the Mac says nothing about the CI's Icarus, which is one reason the adapter refuses case arguments instead of appending them.
- **`wire [31:0] f = $fopen(...)` compiles to a `.sfunc`, not a `%vpi_call`, and still writes the file.** On Icarus 13.0 the compiled program carries one `.sfunc` line for it, and running it created the file (Verified, 2026-09-29). A screen of the compiled program that looks only at `%vpi_call` lines (the SEC-3 idea) misses such a call; screen every quoted `$name`.
- **The committed digital simulation file is a program, and it runs during `validate` before anything calls it stale.** The grammar reads only the sources, and V2's invariants read the file regenerated from the model, so a `$fopen` added by hand to the committed `derived/digital/<id>.v` wrote a file outside the item once per compiled case (14 times) during `validate`; only then did V0 and `v2.dataset-reproduction` fail and each case become `COMMITTED_CASE_STALE` (Verified at `0a5ff00`, Icarus 13.0, 2026-09-29, a scratch clone). This is SEC-2 on the digital path (the SEC-2 decision above names the electrical deck and the Python case scripts): validate only reviewed repository content.
